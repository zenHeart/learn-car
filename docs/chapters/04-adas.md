# 第 4 章 ADAS 等级与感知决策链路

> 能力目标：adas — 按 SAE J3016 区分 L0–L5，并能描述一次 AEB 自动紧急刹车的感知融合、决策与执行链路及失效模式。

## 4.1 SAE J3016 六级定义

SAE J3016 是行业对驾驶自动化的事实标准。每一级都同时考察三个对象：横向控制（转向）、纵向控制（加减速）、环境监控（OEDR，Object and Event Detection and Response）。

- **L0 无自动化**：驾驶员全权控制，ADAS 只做一次性提示（如 LDW 车道偏离预警、AEB 自动紧急刹车虽然动作但只介入不持续控制）。
- **L1 驾驶员辅助**：横向或纵向之一持续控制（典型：ACC 自适应巡航 或 LKA 车道居中保持），驾驶员监控环境并随时接管。
- **L2 部分自动化**：横向+纵向同时持续控制（典型：TJA 交通拥堵辅助、Highway Pilot 高速辅助），驾驶员仍需监控环境并立即接管。
- **L3 有条件自动化**：在 ODD（Operational Design Domain）内系统完成 OEDR，驾驶员可以"分心"但接到接管请求必须在 10 s 内响应。
- **L4 高度自动化**：在 ODD 内系统不要求驾驶员接管，事故责任在系统；ODD 外仍需驾驶员。
- **L5 完全自动化**：任何环境下都不需要驾驶员，方向盘与踏板可取消。

L1 与 L2 的关键区别是"持续还是介入"。AEB（Autonomous Emergency Braking）是 L1 而非 L2，因为它只在检测到即将碰撞的瞬时介入刹车，不持续保持车速——这是入门 ADAS 时最常被混淆的点。

## 4.2 AEB 链路五段

以"前车 30 km/h、相对距离 60 m、本车 50 km/h、TTC ≈ 8.6 s"为例，AEB 链路分为：

1. **感知段**：前视摄像头（前 1V）+ 前毫米波雷达（前 1R）+ 角雷达（4R）。摄像头做车道线/目标分类（car/truck/bike/pedestrian），雷达做距离/相对速度/角度。融合模块用卡尔曼滤波或粒子滤波把多目标关联成稳定 track。
2. **决策段**：ADAS 域控制器（如 Mobileye EyeQ6、英伟达 Orin、地平线 J5/J6）跑 AEB 状态机：SAFE → WARNING → PARTIAL_BRAKE → FULL_BRAKE。状态机依据 TTC 与碰撞概率切换：TTC > 3 s 报警；1.5–3 s 部分刹车；< 1.5 s 全刹车。
3. **执行段**：CAN/CAN FD 把目标减速度请求（例 -0.4 g、-0.8 g）发给 ESC 或 iBooster。iBooster 把驾驶员刹车踏板位置与 ADAS 请求做仲裁：若驾驶员同时踩刹车，取两者中更大的减速度。
4. **反馈段**：ESC 实际减速度与车身 yaw rate 回传到 ADAS 域，用于更新下一周期决策；同时通过 CAN 发送给仪表盘 HMI 显示 AEB 介入图标。
5. **接管段**：AEB 全刹车到停止后，HMI 弹"接管请求"，驾驶员 5 s 内不接管则保持双闪与驻车制动。

## 4.3 失效模式

典型失效：

- **雷达遮挡**：雨雪、泥浆或前保险杠损伤导致 RCS 信号衰减，目标漏检。
- **摄像头逆光/眩光**：夜间对面远光或出隧道瞬时过曝导致车道线丢失。
- **ESC/iBooster 失效**：液压或电控信号丢失时，AEB 请求被 ESC 拒绝，HMI 报"主动刹车不可用"。
- **感知融合错配**：摄像头把摩托车识别为行人、雷达把井盖识别为障碍，造成误刹。
- **驾驶员接管冲突**：AEB 全刹车与驾驶员打方向盘避让同时发生，仲裁逻辑不完善时可能车辆横摆失稳。

## 4.4 测试与验证

ADAS 功能安全标准 ISO 26262 要求 ASIL B/C/D 不同等级（感知 ASIL B，决策 ASIL C/D，执行 ASIL D）。测试要覆盖：

- 仿真：CARLA、PreScan、VTD 等场景仿真，覆盖 10000+ 场景库；
- 场地：Euro NCAP AEB VRU（行人/自行车）、AEB CCR（车对车）、CCRs/CCRb 后追；
- 道路：百万公里影子模式 + 影子里程采集。

1. 为什么 AEB 属于 L1 而不是 L2？
2. iBooster 如何仲裁 ADAS 请求与驾驶员刹车？

## 4.5 ISO 26262 与功能安全

ADAS 每个子系统的 ASIL 等级由"严重度 × 暴露率 × 可控性"三维矩阵算出：

- 严重度：S0（无伤害）、S1（轻伤）、S2（重伤）、S3（危及生命）；
- 暴露率：E1（极低）、E2（低）、E3（中）、E4（高）；
- 可控性：C1（简单可控）、C2（一般可控）、C3（难控）。

例如 AEB 全刹车系统严重度 S3，暴露率 E4（天天遇到），可控性 C3（驾驶员来不及反应）→ ASIL D。

ISO 26262 还要求 ASIL 等级系统在量产前完成：

- 硬件随机失效率指标（PMHF）：ASIL D ≤10⁻⁸/h；
- 软件架构必须满足"无干扰"——不同 ASIL 等级模块之间不能互相干扰；
- 开发流程必须按 V 模型走：概念→需求→设计→实现→测试→验证；
- 安全机制（如双核锁步、ECC、看门狗）必须有故障覆盖率证明。

ASIL 等级直接决定 SoC、传感器与冗余架构的选型。L1 入门时只要记住"AEB = ASIL D 起步"即可。

## 4.6 自检题答案

1. AEB 只在检测到即将碰撞时瞬时介入刹车并立即退出，不是持续保持车速/车距；L2 要求同时持续横向 + 纵向控制，且驾驶员需监控环境随时接管。AEB 是 L1。
2. iBooster 用电机模拟驾驶员刹车踏板力，ADAS 请求与驾驶员输入在 iBooster 内部做"取最大值"仲裁；如果驾驶员踩得比 ADAS 重，按驾驶员意图执行，确保驾驶员永远优先。
3. TTC 1.5–3 s 是"仍来得及避让或部分刹车"的窗口。1.5 s 以下物理来不及全刹，但部分刹车已经能减小碰撞能量；3 s 以上驾驶员仍有接管能力，报警而非刹车避免惊扰。
